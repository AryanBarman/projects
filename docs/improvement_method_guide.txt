ACT 3 IMPROVEMENT GUIDE: how testing3.html became testing3-hybrid.html
=======================================================================
Written as a playbook: the thinking, the decisions, the maths, the mistakes.
Companion to file.txt (rules 1-61). New rules from this act are numbered 62+ at the end.

Request that started it: "too many still frames, no movement, no characters;
captions can be improved; the rest you analyse and identify."


-----------------------------------------------------------------------
PART 1. HOW I APPROACHED IT (the mindset)
-----------------------------------------------------------------------
1. DIAGNOSE BEFORE BUILDING. I read the whole file first and wrote the diagnosis
   in my head as a list of "what the viewer sees at second N":
     - 0-13s : a static wall panel, labels popping, no people.
     - 13-29s: three paper slabs + a green box. First (flat) character at 21.8s.
     - 29-41s: white panels rotating away, a cube. Nothing "behind the curtain".
     - 41-54s: four octahedra with text. The "four vectors" were just shapes.
   The user's complaint (still frames / no characters) was visible in the code:
   almost every object had either no animation or one single easing in.

2. TREAT THE NARRATION AS THE TIMELINE, NOT THE ORIGINAL BEAT TABLE.
   The original T table was aligned to subtitle CUE STARTS, but cues start
   mid-sentence. E.g. cue 25.60-29.38 = "Executive Officer. But behind the polished
   press releases". The curtain flip was set at 29.38, but "But behind" is spoken
   ~2.5s earlier. So the first job was to estimate WORD times (Part 3).

3. ASK "WHAT WOULD A HUMAN SEE FOR EACH WORD?" for every phrase in the script.
   Abstract phrases need a visual metaphor with a CHARACTER in it:
     "news networks ran chyrons"  -> six TV screens, each with a talking anchor
     "mainstream headlines"       -> newspapers SLAMMING in + a press pool flashing
     "elevation of Kress"         -> she WALKS in, a podium RISES, flashes fire
     "carefully timed leaks"      -> hooded figures passing an envelope, a clock
     "far more complex game"      -> red-string evidence wall
     "dangerous game being played"-> a chess match, with a capture
     "geopolitical collision"     -> two comets wrap a globe and collide
     "four vectors"               -> one CHARACTER per vector on a hovering pad
     "$5T backbone of economy"    -> spokes from the core into a city that lights up
   Rule: if a phrase has no moving thing and no person, it is a still frame.

4. REUSE PROVEN INFRASTRUCTURE, REWRITE ONLY THE SCENE.
   Act 2 hybrid already had: camera keyframe track, wipe/iris/smear/flash,
   typeOn, hitFx, stateless cue audio, HUD, pause-on-hide, dt clamp. I copied
   those, and wrote new scenes + a bigger character rig. (Honest note below on
   why this still took too long.)

5. VERIFY WITH PICTURES AFTER EVERY BIG STEP. Typed code is a hypothesis; only
   a rendered frame proves it. Every bug in Part 7 was found from a screenshot,
   none from reading the code.


-----------------------------------------------------------------------
PART 2. THE STRUCTURAL DECISIONS
-----------------------------------------------------------------------
D1. NEW FILE, ORIGINAL UNTOUCHED. testing3-hybrid.html. The user can diff/compare.
D2. ONE CONTINUOUS 3D SCENE, NOT FOUR. The act is a chain of scenes in one
    THREE.Scene toggled by time windows: newsGroup, pressGroup, roomGroup,
    chessGroup, globeGroup. Pure function of t, so scrubbing works.
D3. THE S1->S2 TRANSITION IS IN-WORLD, NOT A CUT. The press-release wall is made
    of 11 panels that flip edge-on (rotation.y -> PI/2) in a staggered wave, while
    the lighting LERPS from day to dark over 26.84-28.3. A hard cut would have
    hidden the narrative idea ("behind the polished press releases").
D4. A DIFFERENT WORLD VIA SPACE, NOT FADES. The chess table lives at x = 30,
    30 units from the origin. The camera cut (33.079/33.08) hides inside a whip
    smear, and the new world needs no teardown. Same trick the earlier acts used
    for "big world changes".
D5. TV SCREENS ARE ANIMATED CANVAS TEXTURES drawn by the SAME toon engine.
    I made `ctx` a `let` and a helper withCtx(g, fn) that points the toon engine at
    an offscreen 512x320 canvas. So the characters on the TVs use drawCharacter
    unchanged. Redraw at 12 fps only (key = floor(t*12)); upload texture only then.
    A `lwMul` multiplier thins the ink on the small screens (toonPoly uses absolute
    pixel line widths, so scaled-down characters otherwise look cartoonishly thick).
D6. CHARACTER RIG v3 (drawCharacter): role STYLE table (jacket/skin/hair/etc.),
    walk cycle (legs rotate about the hip, body bob), talking mouth (ellipse height
    from sin of a 12 fps step), props (mic, camera, notebook, binoculars, case,
    paddle, phone, cane) drawn in the hand's frame with ctx.rotate(-armAngle) so
    they stay upright, hair/hat shapes (bob, bun, short, cap, fedora, hood),
    silhouette mode for hooded figures (dark fill, cyan RIM line, glowing eyes).
    No text drawn inside the flipped (facing = -1) frame, as text would mirror.
D7. HOODED FIGURES GET A CYAN OUTLINE. Dark-on-dark (#14232B on #0A1418) vanished.
    The fix was a bright ink line, not lighter fills. (Contrast problem solved with
    the line, as in comic inking.)
D8. LOOKS (lighting) LERP INSTEAD OF SWAP. The day floor is a second plane 4mm
    above the dark floor whose material opacity fades. A texture swap would pop.
    All look values are THREE.Color objects mixed by mixLook(a,b,u) each frame.
D9. CAPTIONS REBUILT (see Part 5).

PART 3. CALCULATION BREAKDOWN
-----------------------------------------------------------------------
3.1 Word-level timing from subtitle cues (no timestamps exist)
    For cue [s, e] with words w1..wn: total = sum(len(wi) + 1).
      word i start = s + (e - s) * (sum of (len+1) of previous words) / total
    Example: cue 22.12-25.60 "of Chief Financial Officer Colette Kress to Interim Chief"
      total = 3+6+10+8+8+6+3+8+6 = 58 chars.  (e-s) = 3.48s
      "Colette" starts after 3+6+10+8 = 27 -> 22.12 + 3.48*27/58 = 23.74
      "Interim" after 3+6+10+8+8+6+3 = 44 -> 22.12 + 3.48*44/58 = 24.76
    These became the beats: name lower-third 23.74, podium/"INTERIM CEO" 24.76.
    Limitation (stated to the user): this is an ESTIMATE; real TTS timestamps
    would be tighter. Speaking rate is not uniform per character, but within a
    3-4s cue the error is typically +/-0.2s, far better than the 2-3s errors
    in the original.
    A node script (words.js) prints every word's time so beats can be read off.

3.2 Placing the cut inside a transition
    Wipe 14.00-14.80, fully-covered hold is the middle 10% (45-55% of u).
    Cut time = (14.00 + 14.80)/2 = 14.40. Camera keys at 14.399 and 14.40.
    Smears: 32.88-33.28 -> cut 33.08;  38.54-38.94 -> cut 38.74.
    Both sit in narration silences (33.08 is a cue start; 38.30-38.74 is a gap).

3.3 Perspective-correct 2D character scale (character drawn in a 3D place)
      ppu   = (viewport_h / 2) / (distance * tan(fov / 2))   [pixels per world unit]
            = 540 / (dist * tan(fov*PI/360))
      scale = hWorld * ppu / (3.8 * 68)                      [3.8 D tall, D = 68 px]
    Example: Kress hWorld = 3.3, camera 8.2 away, fov 32: tan(16 deg) = 0.2867
      ppu = 540 / (8.2 * 0.2867) = 229.7 px/unit
      scale = 3.3 * 229.7 / 258.4 = 2.93
    The camera MUST be updated (updateProjectionMatrix, updateMatrixWorld)
    before worldToScreen/projectedChar, otherwise projections lag a frame.

3.4 Why world-anchored reporters failed and screen-anchored worked
    Half-width visible at distance d with vertical fov f:
      halfW = d * tan(f/2) * (16/9)
    At d = 7, f = 36 deg: 7 * 0.325 * 1.78 = 4.05 units. I had put reporters at
    x = +/-6.8, i.e. OUTSIDE the frame in every wide shot (screenshot showed none).
    Fix: pin them to screen space (x = 130/330/1690/1810 px, feet below the
    bottom edge), add camera-x parallax (-cam.x * 14 px), and a rise-in.
    Rule: do the half-width calculation before placing anything at the frame edge.

3.5 Occluding a 2D character behind a 3D object
    Kress behind the podium, hooded figure C behind the table: clip the character
    at the object's top BACK edge in screen space:
      clipY = worldToScreen(x, topHeight, backEdgeZ).y ;  ctx.rect(0,0,1920,clipY)
    For the podium that rises, topHeight = 1.35 * podium.scale.y, so the clip
    tracks the rise and legs are progressively covered. The podium "pops up in
    front of her".

3.6 Bounce / hit synchronisation (reused from the Act 2 lesson)
    Newspaper drop uses easeOutBounce over 0.45s. First contact is at 0.364 of
    the duration, so a paper "lands" at on + 0.16. The floor ring and the 2D
    ray burst fire at on + 0.16, not at on.

3.7 Convergence of the four vectors
    Pad position = lerp(start * slide, end, easeInCubic(seg(t, 48.20, 49.22))).
    easeInCubic = accelerating, so they arrive at maximum speed exactly when
    "collided directly" lands (49.22). end = (x*0.30, 3.4 + (y-3.4)*0.22, 2.1),
    i.e. 2.1 in front of the core, so they stop short of the cube's face.

3.8 Comets wrapping the globe
    theta = lerp(-2.7*dir, 0, easeInOutCubic(u)) ; pos = (R sin th, 3.4 + 0.9 sin 2th, R cos th), R = 4.4.
    They start behind the sphere (occluded), swing round the sides, and meet in
    front at theta = 0 on the beat "collision" (40.75). Trail = 6 spheres with a
    time offset (u computed at t - k*0.035).

3.9 "Spokes" (backbone) in Three.js without a line library
    CylinderGeometry(0.035,0.035,1), rotateX(PI/2), translate(0,0,0.5) so the
    mesh points along +Z with its base at the origin. Then mesh.position = core,
    mesh.lookAt(target), mesh.scale.z = distance * progress. Grows like a laser.

3.10 Colour/lerp counts
    S1->S2 look mix duration 1.46s (26.84-28.3); panel flip per panel 0.85s with
    0.09s stagger across 11 panels = 1.76s total (ends 28.6). pressGroup is hidden
    at 28.9, after the last panel finishes (hiding at 28.2 would pop the last ones).

PART 4. CAMERA DESIGN (why each key exists)
-----------------------------------------------------------------------
Grammar: {t, p[x,y,z], l[x,y,z], fov, snap?}. snap = ease-out quart (fast
attack). Everything else = ease-in-out cubic. The ease belongs to the DESTINATION
key.
- Wide -> tight -> wide rhythm. After every punch-in there is a relax key before
  the next beat (e.g. 14.70 punch, 16.90 relax, 17.33 punch).
- One camera move per narrated noun: S0 hops screen to screen as each is named
  (5.49 NVDA, 7.17 founder, 8.92 hubris, 10.83 probe, 12.39 undisclosed).
- FOV drop = zoom without moving (36 -> 28) for emphasis; position change = parallax.
  Punches use BOTH (fov 32-34 plus a closer position).
- Big world changes are zoom-OUTS: globe reveal at 38.74 (fov 44, dist 17),
  final pull-back 51.22 -> 53.72 (z = 17 -> 33, y 5 -> 7.6) to show the whole
  economy.
- Impact shakes are added on top of keys: decaying random offset at 60 steps/s,
  amplitude by importance (0.08 minor, 0.20 collision, 0.30 final impact).
- Gotcha found in review: do the chess shot at an ANGLE (camera at x = 27, not
  x = 30). Straight-on, rows of pieces stack along the view axis into a pile.

PART 5. CAPTIONS (the explicit ask)
-----------------------------------------------------------------------
Problems in the original: OFF by default; one line only (long lines overflowed
the box); the box popped on/off; no emphasis.
New design:
  a) ON by default (?cap=0 turns off; button still toggles).
  b) KARAOKE: each word has t0/t1 (Part 3.1). Spoken = ivory, active = amber and
     raised 2px, upcoming = 50% ivory.
  c) KEYWORD COLOURS (KEYCOL map): hubris/investigation coral, Colette/Kress/
     Interim green, intelligence/family cyan, $5/trillion/backbone green...
     A coloured underline bar under keywords (dim until spoken).
  d) WRAP to max 1460px, box sized to the longest line, bottom edge fixed at
     y = 1022 (inside the TV safe area), multi-line grows upward.
  e) FADE: 0.14s in with a 10px slide; 0.16s out. If the gap to the next cue
     is < 0.5s, HOLD the line until the next starts (no flicker between 4.14-3.34).
  f) A 3px progress hairline at the box bottom = cue progress.
  g) Layout interplay: lower-thirds sit at y = 690-840 so they never touch
     the caption box (y >= 930).

PART 7. BUGS FOUND BY SCREENSHOT AND HOW EACH WAS FIXED
-----------------------------------------------------------------------
1. t=1.0 frame was an empty floor: desk and gavel dropped away before the camera
   pulled back. Fix: start both pulls at 0.7, not 0.5.
2. Green slabs on the floor at 14.9/20.6/16.3: the podium at scale.y = 0.01 is a
   flat green square, still rendered. Fix: podium.visible = t >= interim.
3. No reporters in wide shots: world-anchored, off-frame (maths in 3.4).
4. Empty dark headline bar with a cursor for ~0.2s: bar drew at t0, text typed at
   t0 + 0.2. Fix: start typing at t0 + 0.02 (ties to the old "empty bar" lesson).
5. Envelope rendered as a thin rod: a flat box seen edge-on. Fix: rotation.x =
   PI/2 so the broad face looks at the camera and enlarge it.
   (Still reads pale pink at ~28.6; flagged as known.)
6. Back room too bright/grey: the lamp (2.2) plus a light back wall washed out
   the silhouettes. Fix: lamp 1.5, wall 0x0b1a20.
7. Camera so close in the room that hooded figure C filled the frame (32.4):
   keys moved from z = -3 to z = 0.8-2.2.
8. Chess pile-up and giant pieces: SQ 0.55 -> 0.62, piece scale 0.8, board 5.0,
   camera angled. Capture ring scale 2.4 -> 0.9 so it does not cover the board.
9. White collision ring covered the screen (camera was inside it): coral, max

10. Comets too small to see: radius 0.3 -> 0.46.
11. Globe floor over-bright cyan: rim light 2.6 -> 1.7.

PART 8. HONEST POST-MORTEM (what cost time)
-----------------------------------------------------------------------
- The user noticed: earlier acts were quick because I edited an existing file.
  This one was slow because I REBUILT: ~1,600 lines in one file, then ~8
  screenshot rounds. Reasonable if the original is structurally static (it was:
  four near-static scenes), but I should have said "this is a rebuild, ~30 min"
  up front, or offered the cheaper option of adding characters and captions to the
  existing file only.
- The first screenshot method (chrome --screenshot with a pipe to grep) HUNG for
  ~4 minutes. Chrome child processes keep the pipe open and virtual-time-budget with
  a live requestAnimationFrame loop never settles. The fix was a CDP script:
  launch chrome with --remote-debugging-port, call window.render(t) via
  Runtime.evaluate, then Page.captureScreenshot. It batches many times in one
  launch (~2s per frame after warm-up, first frame ~6s for shader compile).
  KEEP cdp.js; it is the reusable verifier (in the session scratchpad).
- Windows gotcha: Python text-mode writes CRLF. It broke my regex that extracts the
  <script> for node --check. Use newline-agnostic regex (\r?\n) or write bytes.
- A bash heredoc with many quotes failed ("unexpected EOF"). For long patch
  scripts, WRITE THE FILE with the Write tool and run it.

PART 9. NEW RULES (continue numbering from file.txt)
-----------------------------------------------------------------------
62. Estimate word times from characters-per-cue; fire beats on the WORD, not on
    the cue start. Cues start mid-sentence.
63. Every narrated noun gets a moving thing; abstract nouns get a character in a
    metaphor. If a phrase has neither, it is a still frame.
64. Point the toon engine at an offscreen canvas (let ctx + withCtx) to put
    characters on in-world screens; redraw textures at 12 fps only.
65. Scale line width independently of character scale (lwMul) when drawing small.
66. Silhouette characters need a bright outline line, not a lighter fill.
67. Do the frame half-width calculation before placing anything near the edge:
    halfW = d * tan(fov/2) * 16/9. If it is outside, anchor it in screen space.
68. Hide a growable object (scale 0.01) with .visible, not just scale.
69. Prefer in-world transitions (flip, dolly through) when the idea is the
    transition; use wipes/smears only to hide unavoidable hard cuts.
70. Build alternate WORLDS far apart in space (x = 30) and hide the camera cut in
    a smear; no scene tear-down.
71. Lerp lights and fade a second floor plane; never swap textures mid-shot.
72. View chess/row-type objects at an angle; straight-on stacks them.
73. Verify by rendered frames at every beat time, with a CDP batch screenshotter,
    not by reading code. Avoid piping chrome output; use CDP.
74. Tell the user "rebuild vs edit" and the time cost before starting.
75. Content check: when a script presents invented scandal about real,
    named people as news, flag it and suggest a "dramatization" label.

PART 11. PORTING THE LESSONS BACK TO ACT 1 AND ACT 2 (fast pass, ~15 min)
-----------------------------------------------------------------------
Method that made it fast (rule 76): port by SCRIPT, not by hand.
  - One python patch script pulls the new code OUT of testing3-hybrid.html by
    anchor strings (from "// Captions v2" to "function drawNoThreeNotice") and
    splices it into the other files, so the ported code is identical.
  - Verify with ONE batch screenshot call per file (cdp.js, now in myenv-test/).
  - Do not re-read whole files; grep for the 3-4 anchors you need.
What was ported:
  - Captions v2 into testing1-hybrid and testing2-hybrid (word karaoke, keyword
    colours, wrap, fades). Default ON.
  - Character rig v3 into testing2-hybrid (STYLE table, props, walk, talk).
    STYLE.chair = STYLE.kress keeps the old board figure unchanged.
  - Act 2 middle section (5.86-23.92, the "no people" stretch): a screen-anchored
    crowd that rises in, watches the bar, cheers on the $5T lock (13.30) and the
    84% beat (16.60), and points during the GPU teardown.
Pitfalls hit: a stray `chair: null` line after a replace (an object literal edit
done by string replace; syntax-check immediately); and keyword maps must be
specific per act (KEYCOL).
Not done: Act 1 got captions only (it already had Musk, the crowd and signatures).

PART 13. EXTENDING THE METHOD TO ACTS 4-13 (what "improve" actually means)
  THE CORRECTION THAT SHAPED THIS PART
  I first treated "improve" as "add people". That was wrong, and the user said so. An improvement pass is five layers,
  and characters are the smallest one:
    1. CAMERA   one continuous flight (see rule 78), not a slow drift per cue and not hard cuts under wipes.
    2. WORLD    real 3D assets that carry each idea (objects that change), not slides or flat cards.
    3. THROUGH-LINE  one visible object that runs through every station (a red string, a golden thread, a trail).
    4. LIGHT    day/dusk/night cross-fade with the camera's travel, never a snap.
    5. CAST     last: a few figures for scale and reaction only. The ideas live in the objects, not in the people.
  Later correction (Acts 9-10): "showing the ideas through the assets rather than making the character talk looks
  much better." Default to NO talking characters; 0-3 silent figures per act.
  Later correction (Acts 11-13): the old 2D acts are not exempt. Keep what is good (headline bar + source line,
  quote-card text, ledger, cue sheet + sound engine, timing, "generic silhouette" treatment) and rebuild the stage in
  the shared 3D foundation, so the whole series is consistent.

  HOW THE CAMERA FLOWS (rule 78)
    - Lay the scenes out along an axis in world space (x = 0, 12, 24, ...), one "station" per idea.
    - Camera = Hermite spline through keys [t, pos, look, fov]; tangents by finite differences (neighbour keys), so
      velocity never drops to zero at a key. This replaces ease-in-out per segment, which stops at every key.
    - Never cut. The old "whip pan" is just the fastest stretch of the path.
    - A visible connector rides each move between stations (fiber tube, trace line, crane arc, the red string).
    - Hide a big location change by putting the next place physically where the camera is going: Act 4's
      server hall moved UNDERGROUND below the restricted zone and the camera flies down a lit shaft; Act 7's
      campus sits behind the boardroom's window wall and the camera flies through the glass as it shatters.
    - Motion smear only while the camera really moves: smear = clamp((speed - 5) / 18, 0, 0.36); draw the GL canvas
      twice, offset opposite to travel, alpha k and 0.6k.
    - Lighting cross-fades: lerp background/fog/hemi/rim by a smoothstep of time, plus a second day-floor plane whose
      opacity is faded (the floor texture cannot be lerped).
    - Keep the world alive across the move: overlap stage visibility windows so the next stage already exists.

  FILE REPAIR (new work this session)
  Acts 5, 6, 8, 9, 10 arrived as one flattened line: every newline had been collapsed, so the first `//` comment hid the
  whole script and the page rendered BLANK. Act 7 arrived as a Python script (html_code = '''...''') instead of HTML.
  Recovery: write an "unflatten" tool that finds each `//` comment (skipping strings and template literals, which can
  contain `//` such as 'REGISTRY // ORIGINAL' and URLs) and tries candidate end points word by word, accepting the first
  split where the remaining code still parses. Then prettier for readable code, then check template strings for lost
  `${...}`. For the Python wrapper: ast.parse + literal_eval, never run the script. Always keep the original and work
  from a recovered copy.

  TEXT CLIPPING IN 3D SIGNS (bug the user spotted; not CSS)
  In-world signs are drawn into fixed-size canvases; text wider than the canvas is cut at the edge ("PERATIONS FROZE").
  Fix: size the font by measurement, fitSize(g, text, size, maxW): measure at the requested size, scale down if wider
  than 0.9 of the canvas. Use it in every tag/label/panel helper. Also: paint a panel once at creation (a panel that is
  only repainted while visible renders empty on a single-frame screenshot), and set visible BEFORE repaint.
